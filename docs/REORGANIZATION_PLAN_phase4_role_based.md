# WellSight Reorganization — Phase 4: the role-based layout

**Written:** 2026-08-12
**Supersedes:** nothing. This is the successor to `docs/REORGANIZATION_PLAN.md`,
which scoped Phases 0–3. Those shipped (commits `89192d8`, `9412b7b`, `3df97d6`,
`ba7bcec`). This document specifies Phase 4 onward.
**Governing constraints:** file paths are respected. Nothing is deleted.
**Status:** decisions taken 2026-08-12 (§11). Nothing moved yet. Phase 4A starts
once `refactor-package` lands.

## 0. The one-paragraph diagnosis

The tree is organized by **how a file was made**, not **what it is for**.
`derivatives` is a provenance adjective. Everything that is not raw LAZ is a
derivative, so the word carries no information, and the directory became the
default destination for anything that had nowhere else to go. It now holds 116
loose files, nine flat `eval_*` directories, the hand-drawn ground truth, the
model checkpoints, the experiments, and the tile stacks — six different artifact
classes at one depth. The fix is to name directories after **role in the
pipeline**, because role is what determines backup policy, `.gitignore` policy,
and where a person looks for a thing.

## 1. Your four questions, answered

### 1.1 "Why is `derivatives` a base folder?"

Because in the beginning there were exactly two kinds of file: source LAZ, and
things built from source LAZ. That binary was true for about a month. It stopped
being true the moment the project gained:

| Artifact class | Is it "derived"? | Where it lives today |
|---|---|---|
| Hand-drawn annotations | **No.** It is primary input. Irreplaceable. | `data/derivatives/annotations/` |
| Model checkpoints | No. A code artifact, not a raster. | `data/derivatives/tiles/9t/<model>/best.pt` |
| Eval tables and figures | No. A result, the thing the project exists to produce. | `data/derivatives/eval_*/` |
| Candidate well layers | No. The deliverable. | `data/derivatives/experiments/candidates/` |
| DEM / slope / LRM rasters | Yes, genuinely. | `data/derivatives/tiles/<area>/` |

Only the last row belongs under a word like "derivatives". The other four are
there because the folder was the path of least resistance.

The cost is not aesthetic. `annotations/` is 108 MB of work that cannot be
regenerated by any script, and it sits inside a directory whose `.gitignore` rule
is a blanket `data/derivatives/**/*.tif`. One class of file is protected from git
by an exception clause inside a directory whose default is "throw it away."

### 1.2 "Why does it contain `tiles/`, but also all these eval folders for one tile?"

Because `tiles/` is keyed by **area** and `eval_*` is keyed by **question**, and
nobody ever decided which dimension nests inside which. Both got parked at the
same depth, so the top of `derivatives/` reads as a category error:

```
eval_9t_centroid_matching/     eval_9t_pit_thresholds/     tiles/9t/
eval_9t_heldout_overlap/       eval_9t_rim_containment/    tiles/613590_05/
eval_9t_instance_precision/    eval_9t_road_thresholds/    tiles/mk5_1m/
eval_9t_pad_thresholds/        eval_9t_uncounted_wells/    ...
```

Nine siblings of one class, flat, next to a directory that is the correct home
for exactly that class. They are all "scoring the 9t tile" and they should nest
`area → target → question`, three levels, one rule.

Worse: the evidence for a single experiment is split across three trees. Take the
pit U-Net. Its checkpoint is `tiles/9t/pit_unet_cv5/best.pt`. Its probability
raster is `tiles/9t/pit_prob_*.tif`. Its threshold sweep is
`eval_9t_pit_thresholds/`. Its candidate output is `experiments/candidates/`. To
answer "how good is the pit model", you open four directories.

### 1.3 "Why is `label_grids` out on the main directory?"

Because `_build_label_grids.py:46` hardcodes `LABEL_GRIDS = ROOT / "label_grids"`
instead of using `path_for()`, and nothing ever forced the question. That is the
whole reason. It is a build-script accident that became a top-level directory.

Look at what is actually inside `label_grids/westernpa_01/`:

```
dem_westernpa_01_1m.tif        lrm_5_westernpa_01_1m.tif       tpi_25_westernpa_01_1m.tif
dsm_westernpa_01_1m.tif        openness_neg_..._1m.tif         rrim_simple_..._1m.tif
slope_westernpa_01_1m.tif      openness_pos_..._1m.tif         pa1.qgz
chm_westernpa_01_1m.tif        roughness_5_..._1m.tif          westernpa_01_pit_inside.gpkg
                                                               westernpa_01_pit_outside.gpkg
```

That is **a 1 m derivative stack**, byte-for-byte the same artifact class as
`tiles/9t_1m/`, plus a QGIS project and two annotation layers. It is not a new
kind of thing. It is `tiles/<area>/` with an annotation front-end bolted on. The
1.9 GB of rasters belong in the derived tree; the two `.gpkg` files belong in the
truth tree; the `.qgz` belongs with the other QGIS projects.

### 1.4 "Why aren't annotations in the QGIS folder?"

Two things are tangled here and they pull opposite ways.

**Against moving data into `qgis/`:** annotations are the project's primary
ground truth. Eleven training and eval scripts read them. If `roads.shp` lives
under `qgis/`, then the location of the most important data in the repository is
determined by which GUI you happen to draw it in. Swap QGIS for ArcGIS and the
path is a lie. Data does not belong inside a tool directory.

**For your complaint, which is correct:** you edit annotations constantly, and
right now reaching them means `data/derivatives/annotations/` — four levels down,
inside a folder named after regenerable output. That is genuinely bad.

The resolution is to fix the *access path*, not the *storage path*:

- Truth lives at `data/02_truth/annotations/` — one level shallower than today,
  in a directory whose name says "this is irreplaceable."
- `qgis/` becomes the **front door**. It holds one project per job, each
  pre-loading the layers that job needs:
  - `qgis/annotate_9t.qgz` — truth layers editable, hillshade + RRIM basemaps
  - `qgis/annotate_grids.qgz` — the four westernpa grids (replaces the four
    scattered `pa1.qgz`)
  - `qgis/review_candidates.qgz` — model outputs vs truth, read-only
  - `qgis/wellsight.qgz` — the current everything-project, kept
- You open QGIS to reach annotations. You never navigate to them in Explorer.

This is a decision, not a fact. If you want the files themselves under `qgis/`,
say so and I will do it — I would then make `path_for("annotations")` point there
so no script hardcodes a GUI directory. See question 1 in §11.

## 3. Design principles

1. **Name by role, never by provenance.** `source`, `truth`, `derived`, `models`,
   `results`. A reader knows what a directory is for from its name alone.
2. **Regenerability is the primary partition.** `03_derived/` is disposable *by
   definition*. If a file cannot be deleted and rebuilt from a script, it does not
   belong there. This one rule sets `.gitignore` (ignore the whole subtree),
   backup policy (mirror, never snapshot), and recovery (rebuild, never restore).
3. **`02_truth/` is the opposite and is treated as such.** Small, irreplaceable,
   always tracked, snapshotted on every change.
4. **One artifact class, one home, one depth.** No class appears at two depths.
5. **A model is a bundle.** Checkpoint, manifest, training log, prob rasters, and
   eval all live under `04_models/<target>/<run>/`. One directory answers "how
   good is this model."
6. **Study area is a first-class dimension, spelled one way.** Resolution is
   always a directory level, never sometimes-a-suffix.
7. **Every derived leaf carries `_PROVENANCE.json`**: script, args, git SHA,
   input paths, build date. Regenerability stops being folklore.
8. **Scripts do not move.** 93 `sys.path` calls resolve by `parents[N]`. This is
   unchanged from the Phase 0–3 plan and it still holds.
9. **Paths are respected by construction, not by discipline.** Every directory in
   the tree is a key in `config/paths.toml`. No script contains a literal
   subpath. See §5 — this is the load-bearing part of the plan.

## 5. How paths stay respected

This is the section that decides whether the plan is safe. Six mechanisms bind a
path today. Each gets an explicit treatment.

| # | Mechanism | Count | Failure mode | Treatment |
|---|---|---:|---|---|
| 1 | `config/paths.toml` + `path_for()` | 15 keys | loud, one file | **Extend to cover every directory.** Move = value change. |
| 2 | Per-script literal subpaths | ~25 scripts | loud, at run time | **Convert to `path_for()` BEFORE any move.** This is Phase 4A. |
| 3 | `qgis/*.qgz` `<datasource>` | 62 in `wellsight.qgz`, +4 per-grid `pa1.qgz` | **silent** — layer just goes red | `tools/rewrite_qgis_paths.py` against `MOVES.csv`, `.bak` first, Gate B after |
| 4 | `.gitignore` path-anchored rules | ~60 | **silent** — 100 MB file enters history | **Generate from `paths.toml`.** Never hand-edit again. |
| 5 | `sys.path` `parents[N]` | 93 uses | loud, import error | Scripts do not move. Unchanged. |
| 6 | `E:` robocopy mirror | 1 target | **silent** — mirror doubles | §9 |

### 5.1 The rule that makes this work

**No script may contain a directory literal below `ROOT`.** Every path is
`path_for("derived") / area / res / filename`. After Phase 4A, moving a directory
is one line in `paths.toml` plus one `MOVES.csv` run — for code, QGIS, and
`.gitignore` together.

`tools/verify_no_path_literals.py` (new) enforces it. It greps every live `.py`
for `ROOT /` followed by a string literal that is not a `paths.toml` key, and
fails the build. Run it in CI and as Gate E below.

### 5.2 The generated `.gitignore`

Today's `.gitignore` is 10 KB and roughly 60 anchored rules, several of which
already point at directories that no longer exist (`label_grids/permian_01/...`,
`/barlow_data/`, `data/external/ramachandran_2024/...`). It is the single highest
silent-failure risk in the repository.

The role-based tree collapses it to about ten rules, because role determines
policy:

```gitignore
# 03_derived is regenerable BY DEFINITION. Track only the small records.
data/03_derived/**
!data/03_derived/**/
!data/03_derived/**/_PROVENANCE.json
!data/03_derived/**/*.md
!data/03_derived/**/*_preview.png

# 04_models: weights and prob rasters are heavy and regenerable.
data/04_models/**/*.pt
data/04_models/**/*.tif
data/04_models/**/*.tif.aux.xml
data/04_models/**/dataset/

# 01_source: point clouds and third-party bulk downloads.
data/01_source/lidar/**
data/01_source/reference/**/*.zip

# 99_archive: bulk ignored, manifest force-added.
data/99_archive/**
!data/99_archive/ARCHIVE_MANIFEST.csv

# 02_truth and 05_results are small and ALWAYS tracked. No rule needed.
```

`tools/gen_gitignore.py` emits this from `paths.toml` plus a small policy table.
Hand edits to `.gitignore` become a lint failure.

Note what the last comment buys you: today, the irreplaceable annotations are
protected by an exception clause inside a blanket-ignored subtree. After the
move, they are in a directory with no ignore rule at all, so the default is
"tracked" — which is the correct default for the only data you cannot rebuild.

### 5.3 Gates

Every phase ends with all five. No phase is complete until each is clean.

| Gate | Check | Tool | Exists? |
|---|---|---|---|
| A | no >100 MB file unignored | `find` + `git check-ignore` | yes |
| B | every QGIS datasource resolves | `tools/verify_qgis_paths.py` | yes |
| C | every script path constant resolves | `tools/verify_paths.py` | yes |
| D | golden outputs byte-identical | `tools/golden.py` (11 baselines, `729ea93`) | yes |
| E | no directory literals in live code | `tools/verify_no_path_literals.py` | **new** |

Gate D is the one that did not exist for Phases 0–3. It is why Phase 4 can be
more aggressive than Phase 2 was: an 11-baseline harness proves the pipeline
still produces the same numbers after the tree changes shape.

## 9. The backup consequence, stated plainly

`tools/backup_to_E.bat` uses `robocopy /XO`, which **never deletes**. That is
deliberate and correct. It also means a 90 GB restructure does not move anything
on E: — it *adds* the new tree beside the old one. The mirror goes from ~122 GB
to ~212 GB, and half of it is a tree that no longer exists on C:.

Three options, in order of preference:

1. **Replay the moves on E:.** `tools/apply_moves.py --root E:\Colton\_BACKUPS\lidar_project_MIRROR`
   applies the same `MOVES.csv` to the mirror. Same-volume renames, near-instant,
   mirror stays a mirror. **Recommended.**
2. Take a frozen `_SNAPSHOT_prephase4_2026-08-12`, then let the mirror re-copy
   from scratch. Safe, costs ~90 GB of writes and a few hours.
3. Do nothing and accept a stale doubled mirror. Not recommended.

Before Phase 4D starts, take the snapshot regardless. E: has ~4.1 TB free.

## 11. Decisions

Taken 2026-08-12.

| # | Decision | Effect |
|---|---|---|
| 1 | **Truth lives at `data/02_truth/`. `qgis/` is the front door.** | Annotations leave the blanket-ignored `derivatives/` subtree and become tracked by default. Access is through `annotate_9t.qgz`, `annotate_grids.qgz`, `review_candidates.qgz` — three new projects built in Phase 4C. You never navigate to truth in Explorer again. |
| 2 | **Numeric prefixes kept** (`01_source` … `99_archive`). | The tree sorts into pipeline order in every file browser. `config/paths.toml` already reserves the names. |
| 3 | **`refactor-package` lands first, then Phase 4.** | The package will carry one path module to edit instead of 92 scripts. Phases 4A and 4B are safe to run now in parallel; **4C onward waits.** |
| 4 | **Phase 4D moves everything and keeps everything.** | All 19 tile stacks move into `03_derived/<area>/<res>/`. Nothing dropped, nothing archived for size alone. Disk stays ~128 GB; the tree gains one rule and every leaf gains a `_PROVENANCE.json`. The McKean stacks and `inference_613590_05` move with the rest. |
| 5 | **Git history rewrite: yes, but last.** | `git filter-repo --strip-blobs-bigger-than 10M`, 5.4 GB → under 200 MB. Runs only after the tree is settled and a fresh `E:` snapshot exists. Every SHA changes; 21 branches force-push. |

Consequence of decision 4 worth stating plainly: **Phase 4E archives only the
§6.1 items, which are obsolete by evidence.** Nothing is archived because it is
large or because it is quiet. `road_multiblock` goes because the leaderboard
says "Rejected", not because it is 241 MB.
